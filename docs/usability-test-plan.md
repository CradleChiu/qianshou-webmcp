# 目標使用者可用性測試計畫

> 測試版本：P0 示範原型  
> 目的：確認視障使用者能否理解並獨立完成行前資訊查詢  
> 安全限制：本次只測試示範資料，不安排或要求參與者依結果實際出行

## 1. 優先使用者

第一優先招募平常使用螢幕閱讀器或語音操作、能自主決定出行方式的台灣成年視障者。高齡者作為第二組，應另外記錄閱讀、記憶、觸控或行動需求，不把兩組結果混成同一種需求。

建議第一輪招募 3 至 5 人：

- 至少 2 位日常使用手機螢幕閱讀器（VoiceOver 或 TalkBack）。
- 至少 1 位日常使用桌面螢幕閱讀器（NVDA、JAWS 或 VoiceOver）。
- 若有高齡參與者，另外招募 2 位並分組整理結果。

## 2. 測試前準備

- 說明產品仍使用示範資料，不能用於實際出行。
- 取得參與者同意後才錄音、錄影或保存輔具資訊。
- 允許參與者使用自己的裝置、瀏覽器、放大設定與輔具。
- 不要求提供住址；測試一律使用公共場所或參與者自行選擇的非敏感地點。
- 主持人先確認「停止測試」方式，參與者可隨時休息或退出。

## 3. 主持人開場稿

「我們正在測試這個產品，不是在測試你。畫面中的交通與天氣都是示範資料，不能拿來實際出行。過程中請把你正在想什麼、期待發生什麼說出來；如果卡住，我會先記錄，再視情況協助。」

## 4. 任務

主持人不要先示範操作，也不要說出控制項名稱。

### 任務 A：確認資料狀態

請參與者判斷目前頁面提供的資料是否可以用於實際出行。

觀察：是否在開始輸入前理解為示範資料，以及從哪段內容得知。

### 任務 B：建立行程

情境：「你想從台北車站前往台大醫院，希望少走路、少轉乘，而且需要無階梯動線。」

觀察：能否找到起點、目的地、三項偏好與主要操作按鈕。

### 任務 C：理解結果

請參與者說出：

1. 預估時間。
2. 步行時間。
3. 轉乘次數。
4. 下一班車與天氣是否為即時資訊。
5. 哪一項無障礙資訊仍未確認。

### 任務 D：控制朗讀

請參與者開始朗讀、暫停、繼續，再停止朗讀。

觀察：控制項名稱是否容易理解、狀態改變是否有被輔具宣告。

### 任務 E：修正錯誤

請參與者把起點與目的地設為同一地點並送出，再自行修正。

觀察：是否聽到錯誤、是否知道錯在哪裡，以及能否返回正確欄位。

### 任務 F：確認來源與限制

請參與者找出資料來源、產生時間與目前限制。

觀察：折疊內容是否容易發現，以及「產生時間」是否被誤解為官方更新時間。

## 5. 每項任務記錄

每項任務使用相同欄位：

- 結果：獨立完成／提示後完成／未完成。
- 完成時間。
- 錯誤或返回次數。
- 主持人提示次數。
- 參與者原話。
- 使用裝置、瀏覽器、輔具及放大比例。
- 嚴重度：P0 阻止完成、P1 明顯困難、P2 可改善。

## 6. 測試後問題

1. 哪一段最容易？哪一段最不確定？
2. 你會不會把畫面中的數字當成即時資料？為什麼？
3. 你期待用打字、語音或其他方式輸入地點？
4. 結果中最先想知道的是哪三件事？
5. 哪些用詞不像你平常會說的話？
6. 如果正式資料暫時取得不到，你希望產品怎麼告訴你？

## 7. 第一輪通過標準

- 至少 80% 的主要任務可在沒有主持人提示下完成。
- 100% 的參與者知道目前是示範資料，且不會據此實際出行。
- 100% 的參與者能找到路線限制或知道仍有未知事項。
- 沒有鍵盤陷阱，主要流程可由螢幕閱讀器完成。
- 所有 P0 問題在串接正式交通資料前修正。

## 8. 產出

測試結束後整理：

- 一頁測試摘要：參與者組成、任務完成率與最嚴重的三個問題。
- P0／P1／P2 問題清單，每項附證據與建議調整。
- 視障者與高齡者的差異觀察，避免用單一解法概括兩組需求。
- 下一輪原型要驗證的假設，不直接把個別偏好當成普遍需求。
