# 「牽手過路走」產品基礎

> 狀態：產品北極星與第一階段決策  
> 建立日期：2026-08-27  
> 優先順序：產品價值與使用者安全高於競賽需求

## 北極星

讓生活在台灣的視障者與高齡者，在準備出門及移動途中，能用自己習慣的方式取得可信、可理解、可追溯的生活資訊，並保有最後的決定權。

我們不以「替使用者完成一切」為目標，而是減少資訊破碎、介面障礙與不必要的不確定感。

## 第一個使用者承諾

當使用者告訴我們要從哪裡到哪裡，我們會：

1. 理解少步行、少轉乘、無階梯等偏好。
2. 把交通、到站與天氣資訊整理成一份可讀、可聽的行前摘要。
3. 清楚說明資訊來源、更新時間及未知事項。
4. 允許使用者修正，而不是替使用者做不可逆的決定。

## 產品原則

### 視障優先，也服務高齡者

- 先用鍵盤、螢幕閱讀器及語音理解介面，再考慮視覺裝飾。
- 大觸控目標、高對比、可放大、不依賴顏色傳意。
- 語音是第一級介面，但所有重要工作都有非語音路徑。

### 誠實比流暢重要

- 未知就說未知。
- 資料過期就標示更新時間。
- 上游失效不捏造結果。
- 不把一般行程建議說成安全保證。

### Agent 與人共用同一份狀態

- WebMCP 讓瀏覽器 Agent 使用目前頁面的結構化能力。
- 人類 UI 與 Agent tools 呼叫同一套 Domain Services。
- Agent 操作後，使用者能在頁面上檢查、修改及否決。

### 台灣是產品本體，不是翻譯層

- 使用繁體中文、台灣地址、站名、服務與求助資源。
- 優先整合 TDX、中央氣象署等在地官方資料。
- 支援台灣常見口語、地名別稱與交通習慣。

## 安全邊界

「牽手過路走」是生活資訊輔助工具，不是：

- 白手杖、導盲犬或定向行動訓練的替代品。
- 即時判定號誌、車流或是否可以過馬路的安全裝置。
- 醫療、警政或緊急服務的替代管道。
- 未經確認即可付款、叫車、預約或傳送個資的代理人。

## 第一條端到端旅程

> 「我想從台北車站去台大醫院，少走一點、少轉車，順便告訴我現在會不會下大雨。」

完成條件：

- 使用者能輸入起點、終點及行動偏好。
- 系統回傳至少一個標示限制的交通方案。
- 同頁顯示下一班車及天氣摘要。
- 可用鍵盤完成全流程，並可朗讀結果。
- WebMCP Agent 能呼叫相同能力並更新頁面。
- 未連接正式資料時，介面明確標示為開發階段情境資料。

## 第一階段不做

- 全台所有交通模式與無障礙設施完整覆蓋。
- 即時影像辨識及過馬路決策。
- 自動付款、叫車或醫療預約。
- 背景常駐定位與持續追蹤。
- 為了競賽影片而建立無法長期維護的特製流程。

## 成功指標

第一階段以產品品質而非下載量衡量：

- 主要任務可由鍵盤及螢幕閱讀器完成。
- 使用者能說出資料從哪裡來、何時更新。
- Agent 選對工具、參數正確且不越權。
- 上游資料失效時，介面仍提供明確下一步。
- 實際使用者測試能發現並修正至少一項研究文件未預見的問題。
